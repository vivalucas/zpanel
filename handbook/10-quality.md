# 质量与验证

全页 UI 优化专项与当前浏览器矩阵见 [前端验收](../docs/frontend-audit.zh-CN.md) 的当前回归入口。除首次读取失败外，还须覆盖有缓存的后台刷新失败、保存成功后重取失败、401/403/业务鉴权拒绝隐藏缓存与操作，以及上传途中手改后再改回原值；普通同值比较不能代替草稿版本。单图模式还须验证旧失败重试与新文件上传互斥，多文件图库保持并发。界面控件需同时检查可访问名称、320px 实际行布局和浮层动画完成后的视口范围。

原生链接的新标签页快捷键回归使用 Playwright `ControlOrMeta`，随运行平台选择 Control 或 Meta；不能将 macOS 的 Meta 写死到 Linux CI。中键、修饰键和普通点击的 iframe 行为仍分别验证。

壁纸对比度回归在取样前等待空分组按钮的前景色达到标题的目标色，避免将 Ant Design 在壁纸分析或主题切换后的颜色过渡当作最终对比度；仍检查至少 4.5:1，持续的颜色或遮罩错误必须失败。

并行任务不可共用可变 dist、测试输出或同一浏览器服务端口；必要时使用临时源码快照、独立端口和 SQLite，不能将共享构建期间的空白页直接归因于业务代码。`workspace.spec.ts` 后续用例依赖文件前部创建的数据，应运行完整文件，不用 grep 跳过其初始化。Docker 错误布局回归包含浅深/1440px/320px、长技术详情、重试加载和日志失败恢复；弹窗截图及坐标检查须等进入动画结束且边界稳定，不能仅以 visible 判断最终布局。

Docker 入口回归运行 `python3 scripts/docker-entrypoint-test.py`，使用临时路径和 OS 命令模拟，覆盖大 GID、组复用/重名/幂等、未授权组、可选步骤失败继续及基础初始化失败退出，并纳入 Ubuntu CI。它不能代替实际 BusyBox/su-exec；发布前另在无网络独立 Linux 容器中核对 UID/Groups、大 GID 和 socket 读取权限，不以其他生产容器作为动作测试对象。

首页壁纸可读性回归见 `tests/e2e/home-appearance.spec.ts`，包括亮/暗/混合及细纹理测试壁纸的默认文字至少 4.5:1 对比度、文字图标自身底色对比、标题与分组无底板、手机与桌面裁切、主题相反、跨域回退、显式标题与描述色，以及首次提示持久关闭、键盘/触屏入口和访客边界；纯亮度与遮罩计算见 `src/lib/wallpaper.test.ts`。自动检查不代替对真实壁纸与图标的视觉自查。

首页首屏布局回归见 `tests/e2e/home-layout.spec.ts`：桌面、超宽矮屏及手机横竖屏共 7 个基础视口检查首屏图标完整可见、70px 尺寸与搜索点击范围；覆盖自定义/零边距、搜索关闭、两种导航样式的点击与键盘操作，以及监控、首次提示、空分组、加载与异常恢复的文档流。另检查 640/641px 宽、600/601px 高断点及窄矮窗口下的长标题、Logo、秒钟与固定入口不相交，实际命中设置按钮，并走 Tab/Enter/Esc、外观说明及返回首页路径。`toBeVisible()` 不能证明没有遮挡，须结合完整视口、元素交叠与命中检查。测试提供截图及坐标附件，不能代替实际视觉检查或真实手机验收。

历史原验收记录为 15 项 Playwright、9 项 Vitest、test:review、type-check、lint、Go 测试与普通/PWA 构建通过；不作为本次新增验证。
