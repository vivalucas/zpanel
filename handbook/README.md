## 事实与文档分工

代码说明实现，确认需求说明预期，冲突先辨认原因。字段/接口/版本以模型、路由、清单和锁文件为依据，正文补业务含义与例外。根 README 面向使用者，AGENTS 管核心规则，本页管路由/流程，CLAUDE 仅导入；不要各存一份摘要。

## 检查工具

根目录运行 `python3 handbook/tools/check_docs.py --strict-init`（Windows可用 `py`）。检查只读、不联网/执行Git，覆盖核心文件、Claude导入、常见本地文件链接、00/01占位及篇幅；不验证业务事实、锚点、外网或执行合规。Python不可用则人工检查并说明，不为此强制安装；篇幅提醒不是删除指标。

## 开发与协作

开工说明需求、实现差异、范围和验证。小修复简述，跨模块/结构/长期行为先写精简计划；产品含义或兼容性重大取舍先讨论，已授权实现直接完成。并行范围/负责人/依赖记01，共享文件协调顺序；登记不是锁，不覆盖他人修改。

## Git 与跨设备同步

### 项目策略

仅main，无其他分支/工作树；偏离时核对历史和工作区后安全整合。Dependabot自动分支已停，依赖人工审查。提交/推送默认由用户触发；自动模式须明确开启并记录范围，不含版本/标签/Release。

main push运行CI；v*标签或手动工作流触发发行/容器发布。GitHub外部集成未验证，普通同步不授权后续自动提交或发布。

### 开工检查

检查status、分支、upstream，fetch已知remote后比较；失败则远端未知，无仓库则说明。仅开发或授权同步、工作区干净、upstream明确且已核实且只落后时，可 `git merge --ff-only @{upstream}`（PowerShell将 `@{upstream}` 用单引号包裹）；评审/整理不自动合并代码。

有修改不自动stash/reset/清理。分叉先查双方改动、给出整合方案并取得本次整合授权，不自动rebase/合并/强推；缺upstream、远端不明确或分离HEAD先定位，不猜目标。Git看不到其他设备未推送工作，离开前需收工同步；依赖目录、运行数据库和真实.env不通过Git换机，另行迁移。

### 提交与推送

“推送/收工同步”含提交本轮必要改动并推送当前分支；先看diff，只暂存归属明确的文件/片段，已有授权内提交可直接推。推前重新fetch、核对分叉及已知origin/main，推后确认远端目标提交，失败如实说明。未授权不强推、重写共享历史或删分支。提交说明围绕单一目的，可用feat/fix/docs/refactor/chore前缀。

### 版本与部署

普通同步不升级版本/打标签/创建Release；发布请求须核对版本来源、范围并同步版本/说明/验证/标签，生产操作另按具体授权。若push绑定部署但仅授权同步，先说明绑定并确认外部范围，不改CI绕过；已有明确推送部署约定则沿用。

## 日常收尾

依AGENTS完成累计差异及关联路径检查，验证强度匹配影响；多需求须检查交互。UI可运行时实际查看，静态/构建不能冒充视觉验收。验证记录写对象、代码基线（含未提交改动）、方法/结果及未覆盖范围，Windows/macOS/Ubuntu分别说明。

只更新变化的约定与交接；普通结果在对话报告，跨对话缺口进01，重要专项才建报告。长期脚本可引用，临时日志不当永久证据。

## 专项评审（默认只读）

先声明范围/基线、理解实现和约定，再逐项复核；不能只凭关键词判bug。结果分项目理解、确认问题、待验证问题、体验建议；问题附触发/位置/影响/证据/建议/优先级，建议不冒充缺陷。

评审默认不改代码/文档；仅获准保存时写10结论或14+专题报告，修复另按授权。验证不动用户配置/数据库/外部资源，必要时准备隔离环境并说明。自查与独立评审分开，不无限重做全审或保证无bug；获准修复后转开发流程。

## 上下文维护

逐主题更新现行约定、替换当前快照、清掉完成计划和普通过程；保留未决项、用户约束及未提交唯一工作。同类经验合并并保留触发/机制/行动/例外和回归入口，原因归11。原始样本/评测按需保留，不为缩短正文销毁；迁移完成前核对原文，改路由同步修引用并检查，不夹带业务改动。未知项标待复核和依据，发现矛盾在结果说明，不猜测关闭。普通历史交Git，不建无限归档；必要历史注明适用范围与失效原因。

## 信息保护

真实凭据不进文档，样本最小脱敏；发现泄漏说明影响并按授权轮换，不再次复制。规则、锁文件、清单/脚本共享；个人缓存/设置/会话按需忽略，不整目录忽略规则文件。
